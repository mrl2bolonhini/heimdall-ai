Renomeação de Heimdall para Studio: plano em fases

Decisões (26/11/2026): empresa StudioLibre; apps e telas Studio Health, Studio Finance, Studio Games, Studio Memory etc.; comando `studio`; variáveis STUDIO_; domínio studiolibre.io. Repositório: studiolibre/heimdall-ai (o nome do repositório ainda será renomeado na fase 2).

Princípio: nada que roda hoje no Mac pode quebrar. Cada fase se desliga ou volta atrás, e o nome antigo continua funcionando como alternativa durante a transição.

Fase 1 (feita): endereço do GitHub trocado de mrl2bolonhini para studiolibre no README, nos guias e no gerador do site; site regenerado.
Fase 2 (feita em parte: o DNS do www já aponta para studiolibre.github.io; falta renomear o repositório para StudioApps, que só o dono da organização consegue fazer em Settings): renomear o repositório no GitHub; atualizar o endereço remoto das cópias locais (git remote set-url origin); GitHub Pages: o registro CNAME www passa a apontar para studiolibre.github.io (hoje aponta para o usuário antigo).
Fase 3 (código), em blocos pequenos com testes a cada bloco:
 Bloco 1, texto visível (feito em 26/11/2026): nomes de serviço Studio Health, Finance, Games, Memory, Notes, News, Learn, Lab, Account, Controls, Chat, Flows, Status, Trading e Design; StudioLibre na prosa de produto (ajuda, termos, site, README). Preservados de propósito: calendário e lista "Heimdall", lista "Heimdall: Triagem", pastas do Notas, políticas do Access, nomes de contêiner e de modelo, cabeçalhos X-Heimdall-*, o app Heimdall.app e o histórico do CHANGELOG.
 Bloco 3, comando (feito em 26/11/2026): `studio` é a função principal do heimdall.zsh e `heimdall` continua como apelido; ajuda, documentação e testes usam `studio`. STUDIO_DIR vale como alternativa a HEIMDALL_DIR.
 Bloco 2, variáveis STUDIO_* (adiado, fase 3b): os carregadores de .env filtram por prefixo, o Docker (Paperless) lê o .env direto e alguns nomes são combinados com o Worker e com os segredos do GitHub Actions. Fazer sem validar no Mac poderia derrubar o login dos serviços. Plano: script idempotente de migração do .env (acrescenta STUDIO_X a partir de HEIMDALL_X, sem apagar nada), chamado pelo subir.sh, pelo start_heimdall.sh e pelo `studio update`; carregadores aceitando os dois prefixos; nomes combinados com a Cloudflare (CLOUD_SENHA_HASH, TOTP_SEGREDO, CFACCESS_*, R2_*, portas, CONTINUIDADE_*) só na fase 4, junto com o novo deploy do Worker.
 Blocos 4 e 5, módulos, arquivos e pastas de dados (adiado, fase 3b): heimdall_*.py, start_heimdall.sh, macapp/Heimdall.swift e as pastas do Mac, com migração automática, reinstalação dos LaunchAgents e nomes antigos como redirecionadores.
Fase 4 (Cloudflare, com limite de gasto e plano de volta): subdomínios em studiolibre.io (health, finance, games, memory etc.); os endereços de heimdall-ai.tech redirecionam; túnel, aplicativos do Access, roteamento de e-mail (suporte@), bucket do R2 e Workers; deploy da continuidade.
Fase 5: página Marca, CHANGELOG, CLAUDE.md e guias; mensagem de despedida do nome antigo.

Fora do escopo desta renomeação: logomarca e cores (decisão de design à parte); consulta ao INPI (com o usuário).

Decisões complementares (26/11/2026)
1) Serviços x produtos: produtos levam o prefixo Studio (Health, Finance, Games, Learn, Memory, Notes, News, Trading, Lab); serviços de apoio não (Account, Controls, Flows, Status, Chat). O Design continua como Studio Design (documentação do sistema de design). Lab e Chat foram classificados pelo Claude: Lab como produto (ferramenta de estudo de AWS) e Chat como serviço (interface de uma ferramenta de terceiros, como Flows e Status). Se o usuário preferir o contrário, a mudança é só de texto.
2) Subdomínios sem prefixo: health.studiolibre.io etc. (fase 4).
3) Pasta do Mac: ~/heimdall-ai vira ~/studioapps. Cuidados antes de mover: (a) parar os serviços (studio stop); (b) o venv guarda caminhos absolutos e precisa ser recriado na pasta nova; (c) os LaunchAgents do Mac apontam para a pasta antiga e precisam ser reinstalados (subir.sh, agente, app do Mac); (d) a linha source do ~/.zshrc e o HEIMDALL_DIR, se existir, passam para o caminho novo; (e) o Docker (Paperless, Qdrant, n8n) usa volumes relativos à pasta: conferir com docker compose config; (f) depois de mover, rodar studio doctor. Só depois da fase 3b e com uma cópia de segurança. O texto dos guias que cita ~/heimdall-ai troca junto com a mudança real.
